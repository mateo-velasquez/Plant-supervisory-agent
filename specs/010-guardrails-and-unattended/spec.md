# 010 · Guardrails and unattended run — Spec

- **Status:** Implemented
- **Requirements:** FR-15, FR-20 (moved from spec 009), FR-30, FR-31, FR-32, FR-33, NFR-06 (prompt-injection part, moved from spec 009)
- **Stories:** US-08 (moved from spec 009), US-09 (reinterpreted, D9), US-11 (first scenario only)
- **Decisions:** ADR-0016 (hook chain, allowlists, criteria prompt), ADR-0002, ADR-0003, ADR-0009, ADR-0013, ADR-0014, ADR-0015. Q-27, Q-41, Q-43, Q-50–Q-54 (reused); Q-44 and Q-46 amended, Q-55 decided (T12).
- **Week:** W4

## Goal
Make the rules hold even when the model gets them wrong. A hook chain runs before each tool, after each tool and on stop, for both agents. Per-agent allowlists have one source and three barriers in code. The criteria reach both agents as an MCP prompt. The series then advances and closes every shift with no one touching it.

## Scope
- **In:** `hooks/` package (chain, view protocol, allowlist, novelty, floor, cause, completeness); `agents/allowlists.py`; the loop's hook seams and trace records; the `criteria` MCP prompt and `ToolPort.get_prompt`; coordinator prompt v4, investigator prompt v2; the US-08/FR-20 injection tests; one unattended integration over the incident fixture with recorded hook blocks (the demo block).
- **Out:** structured-output validation and caching (011); the one-command CLI, 61 arrivals and the cost/duration report (012); renaming `Coordinator` → `AgentLoop` (deferred); extracting `evals/agent_days_1_7.py`'s composition into `runner/`.

## Decisions
- **D1 · What hooks check (ADR-0016, option B).** Defense over the action plus validation of `texto`. Hooks reuse the code's decisions (the draft's required notices, the decision's metrics, the notice's `causa`) and never recompute a rule.
- **D2 · Where the chain lives.** A `HookChain` (Chain of Responsibility) is injected into the loop class `Coordinator`, used by both agents. The loop always puts the agent's allowlist hook first. The composition root gives the coordinator the rest (`build_coordinator(..., *, hooks=coordinator_hooks())`, required); the investigator gets no extra hook. Hooks read the snapshot through a narrow `SnapshotView` protocol in `hooks/`. `DecisionView` in `runner/coordinator_step.py` satisfies it structurally over the snapshot writer, with no `hooks` import.
- **D3 · Phases.** **Pre-tool** may block: the port is never called, and the reason returns as a tool error. **Post-tool** verifies only: a violation is a code bug and raises (abort, resumable). **On-stop** runs before the loop's `EndReview`: a block is the turn's note; a second note ends in the review's exhausted outcome.
- **D4 · Allowlists (FR-32).** Tool names have one source, `mcp_server/types.py` (`READ_TOOLS`, `WRITE_TOOLS` and one constant per name, moved from `server.py`, which re-exports them). `agents/allowlists.py` is the single source of the per-agent lists (moved from `agents/factory.py`, built from those constants) with `EXCLUDED` = {`set_cause`, `raise_severity`, `lift_severity_raise`}. The list checked, served and offered is one object, `ALLOWLISTS[agent]`. Three barriers: a test, the allowlist hook, a `ValueError` at the composition root. The excluded tools stay registered in `build_server` with their tests.
- **D5 · Criteria prompt (FR-30).** `build_server` registers the MCP prompt `criteria` with the full `criterio.md` text. `build_agent_pipeline` takes it as a required `criteria: str` argument and puts it in `ToolContext.criteria`. The eval scripts read it from `Settings.criteria_path`; tests pass a literal. The loop fetches it once per run and appends it to the role prompt in a `<criterios>` block. Same text for both agents. The prefix is stable across snapshots (011's cache, out of scope).
- **D6 · Failure policy (Q-43).** Repeated blocks consume turns and end in `fallback:turn_cap`; no new limit. Any non-block exception inside a hook (and a post-tool violation) aborts the snapshot: fail-closed, `RunAborted`, resumable, aborted trace line.
- **D7 · Injection (FR-20, US-08).** No detection heuristics. Tests prove that an obeying model cannot close a case or lower a severity. The ADR-0009 hole is documented (X10, E21).
- **D8 · Unattended (FR-33).** `run_series` already advances unattended; 010 adds one integration over the 6-shift incident fixture, which also captures the demo hook blocks deterministically in CI (week-4 deliverable).
- **D9 · US-09 reinterpreted** (story file updated in this PR, T12): (1) emit for a case reported at `alta`/`en_seguimiento` with no change, so not news → "no news since last report"; (2) a `texto` stating "severidad media" for a notice at `alta` → "below notice severity (alta)"; (3) three news at a closing, `emit_shift_report` with two (draft refusal), then the model ends → the stop hook names the missing notices; (4) the investigator calling `apply_proposal`, `emit_alert` or `set_cause` is rejected before the MCP server.
- **D10 · Interface choices** (taken by the spec writer; see plan): **I1** the allowlist hook is built by the loop from its `allowed` list (`ALLOWLISTS[agent]`), so it can never be left out; the `hooks` argument carries only the extra hooks. **I2** hooks run synchronously; pre-tool hooks run in order, and the first block wins. **I3** the novelty set is the cases of the draft's required notices (alerts ∪ report news). A news-only case sent to `emit_alert` passes to the draft, which refuses it (`no alerta_inmediata is decided …`). **I4** hooks read arguments through `hooks/calls.py`, leniently: a malformed argument is skipped, and the server's validation refuses it (X4). `targets(call, view)` gives the floor and cause hooks their `(case_id, notice, texto)` triples. **I5** text patterns run on folded text (NFKD, combining marks dropped, casefolded). Category patterns derive from `CauseCategory` values, so no Spanish wording table is duplicated. **I6** post-tool floor checks every required notice (a superset of the changed ones) whose case is in the last delta, against that case's `minimum_severity` (X6). **I7** a view hook without a view raises `MissingView` (internal error, fail-closed). **I8** the completeness note is rendered by the injected `render_reminder`, the 007 text. **I9** hook records live in `LoopLog.hooks` and are written per line, investigator first. **I10** `criteria` is registered only when `ToolContext.criteria` is set (it stays optional, so the 006–008 tool contexts need no prompt); the loop asks for it only when built with `criteria_prompt`. **I11** the eval scripts read `settings.criteria_path` as `utf-8-sig`, with no other change. **I12** `view` is keyword-only on `Coordinator.run`; the step binds it with `functools.partial` before `run_in_frame`.

## Behavior

### R1 · Hook chain and loop seams (FR-31, D2, D3, I1, I2, I9)
- `Coordinator` holds `HookChain(pre=(AllowlistHook(agent, allowed), *extra.pre), post=extra.post, stop=extra.stop)`. With no `hooks` argument the chain is the allowlist alone.
- **Pre-tool**, for each `tool_use` block in order: `chain.pre_tool(ToolCall(name, arguments), ctx)`. A `HookBlock(hook, reason)` → `ToolOutcome(reason, is_error=True)`, the port is not called, and a `HookRecord(agent, "pre_tool", hook, name, turn, reason)` is appended to `log.hooks`. The `ToolCallRecord` is written as today (`is_error`, `error` = reason). The loop's own `tool <name> is not available` check is removed.
- **Post-tool**, after a call that reached the port and after its `ToolCallRecord`: `chain.post_tool(call, outcome, ctx)` runs every post hook, and an exception propagates.
- **On-stop**, at every `end_turn`: `chain.on_stop(text, ctx)`; a block → its reason is the note and `HookRecord(agent, "on_stop", hook, None, turn, reason)` is appended; otherwise `note = review.review(text)`. One `reminded` flag covers both: the first note is appended as a user turn, a second one returns `review.exhausted`.
- `ctx = HookContext(agent, turn, view)`; `view` comes from `run(..., *, view=None)`.

### R2 · Allowlists: one source, three barriers (FR-32, D4, 009 X9)
- `mcp_server/types.py` holds `READ_TOOLS`, `WRITE_TOOLS` (order unchanged) and one constant per name (`GET_LOGBOOK`, `APPLY_PROPOSAL`, `EMIT_ALERT`, …). `server.py` re-exports the two tuples (`READ_TOOLS as READ_TOOLS`), so its importers are unchanged. `agents/allowlists.py` and `hooks` import from `types`.
- `INVESTIGATOR_TOOLS`, `COORDINATOR_TOOLS` (009 R12 order, unchanged, built from the constants), `ALLOWLISTS` = {`investigator`, `coordinator`} → those tuples, `EXCLUDED`. `build_investigator` and `build_coordinator` offer `ALLOWLISTS["investigator"]` / `ALLOWLISTS["coordinator"]`, and `build_agent_pipeline` builds each server from the same entry. Every test imports the lists from `agents/allowlists.py`.
- Barrier 1 (test): no list meets `EXCLUDED`, and every listed name is in `READ_TOOLS ∪ WRITE_TOOLS` (E6, E24).
- Barrier 2: the allowlist hook (R3).
- Barrier 3: `build_agent_pipeline` calls `check_allowlists(ALLOWLISTS)` before building any server. An excluded tool raises `ValueError("allowlist of the <agent> offers excluded tools: <names>")`, names in list order.

### R3 · Allowlist hook (FR-32, US-09 scenario 4)
A tool name not in the agent's list → `tool <name> is not allowed for the <agent>`. It replaces 007 R4's `tool <name> is not available` (changed expectation, Acceptance).

### R4 · Novelty hook (FR-31a, §4, Q-14, I3)
On `emit_alert` and `emit_shift_report`: every `case_id` (one, or each item of `textos` in order) must belong to a case of `view.alerts() ∪ view.news()`. The first that does not → `<case_id>: no news since last report`. The draft's own refusals (`NotNews`, `NoticeNotDecided`, `ReportNotDecided`) stay as a second line.

### R5 · Text floor hook, pre-tool (FR-15, FR-31b, §2, I5)
- On `targets(call, view)` (`hooks/calls.py`): for `emit_alert`, the alert notice of `case_id`; for `emit_shift_report`, the news notice of each item. Each target is a `(case_id, notice, texto)` triple, kept only when the notice exists and `texto` is a string.
- Matches on the folded text: `\bseveridad\s*:?\s+(?:(maxima)\s*:?\s+)?(?:de\s+)?(ninguna|media|alta|critica)\b`, **skipping** a match followed by `\s*(→|->)` or by `\s+a\s+<level>\b` (a change phrase whose first level is the earlier one, as in the template `severidad media → alta`). Bare words ("alta", "media") never match.
- A plain match is compared with the notice's `severidad`; a `maxima` match with its `severidad_maxima`. The first stated level below it, in text order (items in `textos` order) → `texto for <case_id> states severidad <stated>: below notice severity (<level>)`, or `… states severidad maxima <stated>: …`. Levels are contract values.
- A stated level at or above the record passes (X2).
- The reason names the notice's own severity (its effective floor, possibly raised above the computed minimum), hence "notice severity" rather than US-09's literal "minimum severity" (user decision).

### R6 · Post-tool floor check (FR-15, §2, I6)
After every `apply_proposal` call: for every notice of `view.alerts() ∪ view.news()` whose `case_id` is in `view.floors()`, it requires `severidad ≥ floors[case_id]`. `floors` = `{case.case_id: case.minimum_severity}` for each case of the last delta, as the lifecycle computed it from the snapshot's metrics (never recomputed); `{}` without a delta. A violation raises `FloorViolation("<notice_id>: severidad <s> is below the computed minimum <m> after apply_proposal")`. It is not returned to the model.

### R7 · Cause hook (Q-46 enforced in code, §6, FR-17, I5)
- On the same `targets` as R5. Patterns, one per declared category (not `no_declarada`): the value with `_` or whitespace between its words, word-bounded, on folded text (`parada de línea` ≡ `parada_de_linea`, `retención de calidad`, `faltante de piezas`, `retrabajo`, `ausentismo`).
- The first category named (text order) that differs from the notice's `causa.categoria` → `texto for <case_id> names cause <named>; its causa is <categoria>`. With `no_declarada`, naming any declared category blocks.

### R8 · Completeness on stop (FR-31c, §4, I8)
Coordinator only. At `end_turn`, a non-empty `view.missing()` → block with `render_reminder(missing)` (`Texts are still missing for these notice ids; write them with the write tools: <ids>`). It replaces `MissingTexts` inside the chain. `MissingTexts` stays the default review: its `exhausted` gives `fallback:missing_texts` (007 R3 unchanged). The investigator has no stop hook; `ProposalReview` stays its review.

### R9 · Failure policy (Q-43, NFR-10, D6, I7)
- A blocked call costs its turn. Blocks repeated to `max_turns` end in `fallback:turn_cap`; template texts stand and the snapshot commits.
- An exception raised by a hook (internal error, `MissingView`, `FloorViolation`) is never caught by the chain or the loop. It leaves `run_in_frame` as the leaf (single-exception groups unwrapped, 009 X5). The pipeline writes an aborted line with the records so far, `hooks` included, and `run_series` raises `RunAborted`; nothing of the snapshot commits.

### R10 · Trace hook records (Q-44 amended, FR-37)
`TraceLine.hooks` becomes `list[TraceHook]`: `{agent, phase, hook, tool, turn, reason}`, with `phase` ∈ {`pre_tool`, `on_stop`} (post-tool never blocks) and `tool` null on stop. Records are written at line level, the investigator's then the coordinator's, on committed and aborted lines. Old lines with `"hooks": []` or with no key parse to `[]`.

### R11 · Criteria MCP prompt (FR-30, D5, I10, I11)
- `ToolContext.criteria: str | None = None`. `build_server` registers the prompt `CRITERIA_PROMPT` (`"criteria"`, in `mcp_server/types.py`) when it is set, returning the text unchanged, for any `tools` selection.
- `ToolClient.get_prompt(name) -> str` joins the text of the prompt's messages. An unknown prompt raises `ValueError("prompt <name> is not available")`; no `mcp` type leaks. `ToolPort` gains the same method.
- A loop built with `criteria_prompt` fetches it once per `run`, after `list_tools`, and sends `compose_system(role, criteria)` = `f"{role.rstrip()}\n\n<criterios>\n{criteria.strip()}\n</criterios>"` on every request of that run. Without `criteria_prompt`, the system is the role prompt as today.
- `build_coordinator` and `build_investigator` set `criteria_prompt = CRITERIA_PROMPT`.
- `build_agent_pipeline(settings, registry, ctx, policy, model, trace, criteria: str)` (required) puts `criteria` into `ToolContext(criteria=...)`; it reads no file.
- `Settings.criteria_path` is a derived property, `rules_dir / "criterio.md"`, next to how `umbrales.yaml` is located; there is no new env var. `evals/agent_days_1_3.py` and `evals/agent_days_1_7.py` pass `settings.criteria_path.read_text("utf-8-sig")`. Tests pass the CRIT literal.

### R12 · Prompts (ADR-0002)
- **Coordinator v4:** title `# Coordinator prompt v4`, 009 R13 headings unchanged. `## Role` gains one line: "The plant's rules are in the `<criterios>` block below. Code has already computed every number and decision they define: use them to understand the brief, never to recompute it."
- **Investigator v2:** title `# Investigator prompt v2`, 009 R13 headings unchanged, the same line in `## Role` with "the brief" → "the logbooks".

### R13 · Injection defense (FR-20, NFR-06, US-08, D7)
An obeying model is stopped by code: schema control (`close_case` is no proposal type), the allowlist hook (the reader cannot write; the writer cannot read logbooks), `ProposalBook` (unknown ids), and the floor (no tool lowers a severity or closes a case). The ADR-0009 hole stays: a verbatim injected line in a later logbook passes `verify_citation`, and its worst effect is a lift back to the code floor.

### R14 · Unattended run (FR-33, US-11 scenario 1)
`run_series` with `build_agent_pipeline` and a scripted model processes the 6-shift incident series in one call. With hook blocks, a fallback and a missing logbook it emits one report per closing, never aborts and needs no manual step.

### R15 · Import boundaries
`hooks` imports only `domain`, `mcp_server.types` and `hooks` (from submodules; `hooks/__init__.py` holds a docstring only); never `agents`, `runner`, `cases`, `metrics`, `logbooks`, `mcp_server` (other than `types`), `config`, `anthropic` or `mcp`. `agents` adds `hooks` to its allowed imports. `agents/allowlists.py` imports only `telemetry` (for `AgentName`) and `mcp_server.types`. `runner/coordinator_step.py` does not import `hooks`: `DecisionView` satisfies `SnapshotView` structurally. `cases`, `metrics` and `evaluation` rules are unchanged.

## Edge cases and assumptions
- **X1** · Paraphrases slip (ADR-0016 risk): "línea parada", "subió a alta", plural "retrabajos" (E10f). Patterns stay narrow on purpose; the paid run and evals measure what passes.
- **X2** · A stated severity above the record ("severidad crítica" on an `alta` notice) is not blocked: FR-15 is a floor. An upward misstatement is out of 010.
- **X3** · In a change phrase only the earlier level is skipped; the later one is not checked (E8b, E8c). This keeps the template's own `borrador` passing.
- **X4** · A malformed argument never blocks and never raises in a hook (E13): model mistakes are tool errors from the server, not aborts.
- **X5** · A case with both an alert and a news item at a closing: `emit_alert` is checked against the alert, `emit_shift_report` against the news. Both come from the same facts.
- **X6** · A news item for a case resolved earlier in the shift has no floor (its case is not in the last delta), so the post-tool check skips it (E9d).
- **X7** · The investigator's chain is the allowlist alone; it runs with `view` None and keeps `ProposalReview` as its end review.
- **X8** · With completeness in the chain, `MissingTexts` never writes the note, but it still gives `fallback:missing_texts` and serves loops built without that hook (007 E8 unchanged).
- **X9** · A text describing data with a category word ("unidades en retrabajo") for a notice whose `causa` differs is blocked (Q-55, decided by the user): code cannot tell a data description from a named cause, and a blocked text is rewritten or falls back to the template.
- **X10** · ADR-0009 hole: a line injected verbatim into a later logbook passes `verify_citation`. The worst effect is a lift back to the minimum (E21). No detection heuristics.
- **X11** · `criterio.md` is our own file: it is not escaped inside `<criterios>`, and it is the same text for both agents (about 1,500 tokens per request, ADR-0016).
